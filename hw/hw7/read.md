### 複雜度與全方位比較

設字串 $S$ 長度為 $M$，正規表達式 $P$ 長度為 $N$：

| 比較維度 | 動態規劃 (2D DP) | 純回溯法 (Backtracking - 非 DP) | Thompson NFA 狀態集合模擬 |
| :--- | :--- | :--- | :--- |
| **時間複雜度** | $O(M \times N)$ | 最壞 $O(2^{M+N})$（指數級爆炸） | $O(M \times N)$ |
| **空間複雜度** | $O(M \times N)$（可優化至 $O(N)$） | $O(M + N)$（遞迴呼叫堆疊） | $O(N)$（僅需儲存當前活躍狀態集） |
| **重複子問題處理** | 透過二維表格完整記錄，不重複計算 | 完全不記錄，相同子問題算無數次 | 透過 `Set` 自動去重（天然避免重複狀態） |
| **提早終止 (Early Exit)** | 較難（標準 Bottom-up 需填完表格） | 找到第一條成功路徑即刻返回 | 支援（若 `current_states` 為空可立刻宣告失敗） |
| **實務應用場景** | 演算法競賽、教學、需回溯完整對齊路徑時 | Python `re`、PCRE、JavaScript<br>（為了支援 Backreference 反向引用） | GNU `grep`、Go `regexp`、Rust `regex`、Google `RE2` |

---

### 四、 深度總結：本質是一體兩面

#### 1. 為什麼 DP 與 Thompson NFA 的時間複雜度都是 $O(M \times N)$？
仔細觀察會發現，在 Thompson NFA 中，處理第 $i$ 個字元時，`current_states` 集合裡若包含狀態 $j$，就完全對應於 DP 表格中 `dp[i][j] == True`。
* **DP** 是站在「**矩陣填表**」的視角，把所有 `True` 和 `False` 全部算出來。
* **Thompson NFA** 是站在「**圖論狀態轉移**」的視角，只收集值為 `True` 的索引 $j$ 往下一步傳遞。

#### 2. 為什麼現代程式語言（如 Python / JS）的 Regex 預設不用 DP 或純 NFA，反而用會爆炸的回溯法？
因為當正規表達式需要支援**反向引用（Backreferences，如 `(a+)\1`）**時，狀態不再只取決於位置 $j$，還取決於前面捕獲群組的實際內容。此時已不具備單純的無後效性與固定狀態數，NFA 與 $O(MN)$ 的 DP 均無法直接處理，只能退回使用回溯法。
