# 2^n 演算法效能與時間複雜度展示

這份程式碼是一個非常經典的演算法效能與時間複雜度（Time Complexity）展示。透過計算 2^n 的四種不同實作方式，證明了**「程式邏輯的差異，會讓執行時間從一瞬間變成一輩子」**。

## 🚀 四種核心計算方法

這四種方法雖然都能算出 2^n，但在效能與運作機制上有著天壤之別：

| 方法名稱 | 實作函數 | 時間複雜度 | 特點說明 |
| :--- | :--- | :---: | :--- |
| **方法 1：內建運算子** | `power2n_v1` | O(1) | **最快。** 直接呼叫 Python 內建的次方運算子 (`2 ** n`)，由底層優化過的 C 語言直接執行，幾乎不耗時。 |
| **方法 2a：雙重遞迴** | `power2n_v2a` | O(2^n) | **極慢（指數爆炸）。** 標準雙重遞迴 (`f(n-1) + f(n-1)`)。計算過程會展開成巨大的二元樹，產生海量重複計算。當 `n=100` 時，就算到宇宙毀滅也算不完。 |
| **方法 2b：單一遞迴** | `power2n_v2b` | O(n) | **快。** 改成單一遞迴 (`2 * f(n-1)`)，將運算次數降為線性。缺點是 `n` 太大時會觸發 Python 的「最大遞迴深度限制（預設 1000）」而報錯。 |
| **方法 3：遞迴 + 查表** | `power2n_v3` | O(n) | **快。** 保留雙重遞迴結構，但加入字典 `_table` 當快取（Memoization）。算過的值直接「查表」，成功解決重複計算，為**動態規劃（Dynamic Programming）**的核心精神。 |

## 🛠️ 測試與驗證模組

程式碼下半部設計了四個測試區塊，用來驗證理論與觀察效能差異：

### 1. `run_with_timeout` (超時中斷機制)
- **原理**：利用 Python 的 `signal` 模組設定「系統鬧鐘」。
- **作用**：因為「方法 2a」在 `n > 30` 時就會算非常久，設定只要計算超過 5 秒（`TIMEOUT = 5`），系統就會拋出 `TimeoutError` 強制中斷，避免整個測試卡死。

### 2. `check_correctness` (正確性驗證)
- **作用**：先用較小的數字（`n=20`），讓四種方法都跑一遍。
- **目的**：確保大家輸出的答案都等於 `1,048,576`，證明「大家的邏輯都是對的，單純是效能不同」。

### 3. `growth_test_v2a` (指數成長觀察)
- **作用**：專門針對最慢的「方法 2a」進行壓力測試。
- **觀察**：印出 `n=10, 15, 18, 20, 22` 時的花費時間與呼叫次數。你會看到 `n` 每增加 1，運算量與時間就會嚴格「翻倍」，完美展示指數型成長的恐怖。

### 4. `compare_at_n100` (終極對決)
- **作用**：將 `n` 設為 `100` 進行效能極限測試。
- **結果**：
  - `v1`, `v2b`, `v3` 都能在 `0.000...` 秒內瞬間給出正確答案。
  - `v2a` 會在 5 秒後觸發 Timeout 被強制中止（其實際所需計算次數高達 2.5 × 10^30 次）。

---
**💡 核心結論**：在軟體開發中，選擇正確的演算法，遠比提升電腦硬體速度更重要。
